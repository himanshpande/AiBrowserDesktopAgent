# Step 4 – Building the Project

After configuring everything, we executed

```bash
npm run build
```

At first glance this looks like a very simple command.

However, internally many different processes happen.

Let's understand them one by one.

---

# Internal Build Flow

```
npm run build

        │

        ▼

TypeScript Compiler

        │

        ▼

Checks Type Errors

        │

        ▼

Vite Build Starts

        │

        ▼

React Components Compiled

        │

        ▼

        │

        ▼

manifest.config.ts

↓

manifest.json

        │

        ▼

dist Folder Generated

        │

        ▼

```

This is the complete lifecycle of our build.

---

# What is the dist Folder?

Many beginners believe

```
dist
```

is just another folder.

It is not.

The dist folder contains the **production-ready** version of our project.

Everything that Chrome executes comes from this folder.

Chrome never reads files directly from

```
src/
```

Instead,

Chrome reads

```
dist/
```

---

# Typical dist Structure

```
dist/

│

├── assets/

├── index.html

├── manifest.json

└── ...
```

Notice something interesting.

We never created

```
manifest.json
```

ourselves.

It was automatically generated by CRXJS.

---

# Why Does CRXJS Generate manifest.json?

Because Chrome understands only

```
manifest.json
```

It does not understand

```
manifest.config.ts
```

The plugin converts our TypeScript configuration into JSON during the build.

Flow

```
manifest.config.ts

↓

CRXJS

↓

manifest.json
```

# First Error We Faced

Our first build failed with the following error.

```
Could not resolve './index.css'
```

At first,

this error looked confusing.

Let's understand why it happened.

---

# Why Did This Error Occur?

Earlier,

we removed

```
src/index.css
```

because we wanted a clean project.

However,

inside

```
main.tsx
```

we still had

```ts
import "./index.css";
```

During the build,

Vite searched for

```
index.css
```

Since the file no longer existed,

the build failed.

---

# Fix

We removed

```ts
import "./index.css";
```

from

```
main.tsx
```

The corrected file became

```ts
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import App from "./App";

createRoot(document.getElementById("root")!).render(
    <StrictMode>
        <App />
    </StrictMode>
);
```

After this,

the build completed successfully.

---

# Debugging Lesson

Whenever Vite reports

```
Module not found
```

always ask yourself

> "Did I delete a file that is still being imported?"

This is one of the most common beginner mistakes.

# Step 5 – Loading the Extension into Chrome

After the build succeeded,

our next task was installing the Extension inside Chrome.

We opened

```
chrome://extensions
```

Then we enabled

```
Developer Mode
```

Finally,

we clicked

```
Load Unpacked
```

and selected the

```
dist
```

folder.

---

# Why Did We Select dist Instead of src?

Chrome does not understand React source code.

Chrome understands only the compiled Extension.

Therefore,

we always select

```
dist/
```

Never

```
src/
```

---

# Internal Chrome Loading Process

When we select

```
Load Unpacked
```

Chrome performs the following operations.

```
Read Folder

↓

Search manifest.json

↓

Validate Manifest

↓

Load Popup

↓

Load Icons

↓

Register Extension

↓

Display Icon
```

If any step fails,

Chrome refuses to install the Extension.

# Best Practices

✔ Always use Manifest Version 3.

✔ Keep the Manifest file clean.

✔ Build before testing.

✔ Load only the dist folder.

✔ Remove unused imports.

✔ Keep popup width between 300–400 pixels.

✔ Never edit generated files inside dist.

---

# Common Beginner Mistakes

❌ Editing manifest.json inside dist.

Instead,

edit

```
manifest.config.ts
```

and rebuild.

---

❌ Loading src folder into Chrome.

Always load

```
dist/
```

---

❌ Forgetting to install CRXJS.

Without it,

the project remains a normal React application.

---

❌ Deleting files without removing imports.

This was the exact mistake we encountered with

```
index.css
```

# Interview Questions

### Q1. What is Manifest V3?

Manifest V3 is the latest specification for Chrome Extensions. It defines how an extension is configured and what resources Chrome should load.

---

### Q2. Why do we use CRXJS?

CRXJS allows Vite projects to be built as Chrome Extensions by generating the required manifest and packaging the project correctly.

---

### Q3. Why does `default_popup` point to `index.html` instead of `App.tsx`?

Because Chrome cannot execute React components directly.

React always starts from

```
index.html

↓

main.tsx

↓

App.tsx
```

---

### Q4. Why do we load the dist folder?

Because it contains the compiled production-ready Extension that Chrome can execute.

---

### Q5. Why did the build fail?

Because

```
main.tsx
```

was importing

```
index.css
```

even after the file had been deleted.
